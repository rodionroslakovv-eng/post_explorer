# Post Explorer

SRS 8 — Flutter-приложение для просмотра, поиска и создания постов (API: [JSONPlaceholder](https://jsonplaceholder.typicode.com)).

Студент: Росляков Родион, группа 23.314, кафедра «Бизнес-информатика».

Стек: Flutter, Dio, Retrofit, json_serializable, Provider (ChangeNotifier), SharedPreferences.

## Запуск

```bash
# 1. Платформенные папки (android/ios/web/windows) создаются один раз
flutter create . --project-name post_explorer --platforms=android,ios,web,windows

# 2. Зависимости
flutter pub get

# 3. Генерация *.g.dart (json_serializable + retrofit_generator)
dart run build_runner build --delete-conflicting-outputs

# 4. Запуск
flutter run

# 5. Тесты (+ отчёт для сдачи)
flutter test --reporter expanded > docs/test_report.txt
```

Для Android release-сборки в `android/app/src/main/AndroidManifest.xml` должно быть
`<uses-permission android:name="android.permission.INTERNET"/>` (в debug добавляется автоматически).

Если `pub get` ругается на версии, выполните `flutter pub upgrade`.

## Запросы (Retrofit)

| № | Метод | Endpoint | Где используется |
|---|-------|----------|------------------|
| 1 | GET | `/posts?_page&_limit` | список, пагинация |
| 2 | GET | `/posts/{id}` | экран деталей |
| 3 | GET | `/posts?userId={id}&_page&_limit` | фильтр по автору |
| 4 | GET | `/posts/{id}/comments` | комментарии |
| 5 | POST | `/posts` | создание поста |
| + | GET | `/users`, `/users/{id}` | список авторов, карточка автора |

## Как приложение ведёт себя (задание E)

- **Первый запуск, сеть есть.** Кэша нет, показывается индикатор загрузки. Приходят 10 постов, список отображается, кэш записывается.
- **Повторное открытие.** Сначала мгновенно показываются сохранённые посты с плашкой «Показаны сохранённые данные. Обновляем…» и тонким индикатором. Параллельно идёт запрос первой страницы. После успеха список заменяется свежими данными, плашка исчезает, кэш обновляется.
- **Нет интернета (кэш есть).** Остаётся кэшированный список, плашка меняется на «Показаны сохранённые данные. Нет подключения…» с кнопкой «Обновить». Последний успешный результат не удаляется. Работают детали из списка, поиск и сортировка по загруженным данным.
- **Нет интернета (кэша нет).** Экран с ошибкой и кнопкой «Повторить». Приложение не падает.
- **Pull-to-refresh.** Заново грузит первую страницу, текущие данные остаются на экране до ответа. При ошибке данные не стираются.
- Кэш хранится отдельно для «всех авторов» и для каждого автора. Вторые и следующие страницы дописываются в кэш без дублей.

## Состояния UI

- Список: `ListStatus` (loading / success / cached / error) + пустое состояние (Empty) в экране. Подгрузка страницы — отдельный `PageStatus` (idle / loading / error). Обновление — флаг `isRefreshing`. Одного общего `isLoading` нет.
- Детали: пост, автор и комментарии — три независимых `AsyncValue` (loading / success / error), у каждого своя кнопка повтора.
- Создание: отдельный `SubmitStatus` (idle / submitting / success / failure) в `CreatePostController`.

## Обработка ошибок

`AppException.from(...)` различает: нет соединения, таймаут, HTTP 4xx, HTTP 5xx, ошибку JSON, неизвестную ошибку (и служебный `cancelled`). Цепочка: `ErrorInterceptor` (Dio) → `Repository._guard` → контроллер → UI. Пользователь видит `message`, технические детали (`technical`) пишутся только в `debugPrint` в debug-режиме.

Некорректный JSON (нет обязательного поля) даёт `TypeError` в сгенерированном парсере, репозиторий превращает его в `AppException(parse)`, приложение показывает сообщение и не падает.

## Пагинация, поиск, фильтры

- Старт — 10 постов, подгрузка за 240 px до конца списка, кнопка «Загрузить ещё», индикатор внизу.
- Защита от дублей: множество страниц «в полёте» + статус `PageStatus.loading` + дедупликация по `id`.
- Ошибка страницы: сообщение и кнопка «Повторить», автоподгрузка при этом не зацикливается.
- Смена фильтра: страницы сбрасываются, старый запрос отменяется (`CancelToken`), ответы устаревших запросов игнорируются по счётчику поколений.
- Поиск по заголовку **локальный**, в интерфейсе подписано «Поиск только среди загруженных постов (N), не по всему набору данных».
- Сортировка по ID (↑/↓), переключатель автора («Все авторы» / конкретный), кнопка «Сброс».

## Создание поста

Форма с валидацией (title 5–100, body 10–1000, автор из списка), кнопка блокируется на время запроса. После ответа показывается объект, который вернул сервер. Пост добавляется в локальный список с пометкой «создан локально». JSONPlaceholder всегда отвечает `id = 101` и ничего не сохраняет, поэтому локальным постам выдаются уникальные id (101, 102, …). Локальные посты сохраняются на устройстве.

## Дополнительное задание

Выбрано: **отмена запросов**. Retrofit-методы принимают `CancelToken` (`@CancelRequest()`), контроллер отменяет предыдущий запрос при смене фильтра и обновлении, а результаты устаревших запросов дополнительно игнорируются.

## Зачем это всё нужно (для защиты)

- **Dio** — HTTP-клиент: базовый URL, таймауты, interceptors (заголовки, логи, ошибки) настраиваются один раз и действуют на все запросы.
- **Retrofit** — описывает API декларативно (аннотации над методами), генерирует код запросов. Нет ручной сборки URL и параметров, меньше ошибок и дублей.
- **json_serializable** — генерирует `fromJson` / `toJson`. Нет ручного парсера, типы проверяются, nullable-поля и вложенные модели обрабатываются единообразно.
- **Repository** — единственный источник данных для UI. Скрывает, откуда данные (сеть или кэш), обновляет кэш, приводит любые ошибки к `AppException`. UI и тесты не зависят от Dio и Retrofit.
- **Слои**: Presentation отвечает за отображение и состояние, Repository за правила работы с данными, Remote/Local data sources за доступ к сети и хранилищу. Любой слой можно заменить или подменить в тесте, не трогая остальные.

## Ограничения

- JSONPlaceholder не сохраняет изменения: созданные посты существуют только локально.
- Фильтр `userId` вместе с `_page` / `_limit` поддерживается сервером, всего 100 постов (10 страниц).
- Локальный кэш — SharedPreferences: подходит для сотен постов, для больших объёмов нужен Hive/Isar/SQLite.
